## 3. Original behaviour deliberately replaced (the only functional removals)
1. **`RegisterController::stage1` "resume an unfinished registration by email alone"** (overwrote the password and issued a login token — an account takeover) → resume-by-emailed-code (Task 2).
2. **`RegisterController::stage1` "create the account immediately and return a token"** → (final round) stage 1 creates nothing and answers every email identically; the account is created at `/register/verify` after the emailed code. This closes the email/phone enumeration, the junk-account creation and the OTP/Telegram abuse. **It changes the registration journey** (stage 1 → code → continue) and requires a working mailer.
3. **Original stage-1 mail-failure disclosure** (`email_sent:false`, "could not send") → identical response in every case; failures are recorded server-side and the code is unusable.
4. **Referral code generation** `strtoupper(Str::random(8))` → `ReferralService::newCode()` (collision-checked, same length; existing codes unchanged).
5. **`InvestorWithdrawalController::store()`** restructured by Task 5 (reviewed; no defect found).
6. **Tests replaced/updated for the new contracts** (assertions preserved in intent): `PrivacyPolicyRegistrationTest`, `RegistrationRoleSecurityTest`, `RegistrationEmailTest` (2 tests replaced), Task 2's `RegistrationResumeSecurityTest`, Task 5 registration helpers; one assertion in `MySqlApprovalConcurrencyTest` corrected (counting only).
