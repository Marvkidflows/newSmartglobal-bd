## Changes made this round that touch security
* **Delegated staff:** new `my/permissions` endpoints return only the caller's own grants and are refused for non-staff. Menus are conditional, but the APIs enforce the same permissions independently.
* **Registration enumeration (closed by design, except phone-after-email-proof):** stage 1 no longer creates an account/token/alert and answers every email and phone identically; the account is created only at `/register/verify` after an emailed code; staff/completed/inactive emails receive nothing and the same response; per-address (database) and per-IP limits, response-time floor. Residual: a visitor with a readable mailbox can still learn that a phone is registered, after a correct code, budgeted per IP — closing it needs SMS proof or a business-rule change (Management). See `REGISTRATION_SECURITY_REMEDIATION_REPORT.md`.
* **Registration export** (lead/admin only, current filters, ≤5,000 rows, throttled 5/min, formula-injection-safe, excludes ID numbers/documents/phones/financial data, audited as `report_exported`) and **staff password change** (current password required, must differ, throttled, signs out other sessions, audited).
* **Referral scan scheduled hourly** with `--no-backfill`; never approves/credits; logs only changes.
* **RegistrationResume safeguards (unchanged, documented):** atomic verify-and-apply relies on **InnoDB transactions** — do not run on MyISAM. **Rotating `APP_KEY` invalidates in-flight resume codes** (they live 10 minutes; owners simply request a new one).

## Residual risks
Everything above is unexecuted. Distributed enumeration (many IPs) is only slowed. Admins can still draft and approve a policy alone and one Financial user can approve and credit a reward (see MAKER_CHECKER_PROPOSAL.md). The MySQL concurrency failure recorded in the old results file is unexplained (STALE_RESULTS_INVESTIGATION.md).

## Additions in the final-remediation round
* **Dual-approval bypass closed:** referral credit/reversal and the (disabled) fee refund now refuse amounts at or above the ORIGINAL `balance_threshold_usd`, so they cannot skip the original second-approver rule (`WITHDRAWAL_FINANCIAL_SECURITY_REVIEW.md` §5).
* **Withdrawal flow reviewed** (submission, approval, rejection, fees, ledger, locks): no defect found; observations in the review (§4). **Concurrency not yet executed** — `MYSQL_CONCURRENCY_INVESTIGATION.md`.
* Maker/checker: the original engine is described; no authority changed (`MAKER_CHECKER_PROPOSAL.md`).
