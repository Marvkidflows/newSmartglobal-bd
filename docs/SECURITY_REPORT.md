# Security report (F-10…F-12, F-15; unexecuted unless stated)
## F-11 XSS / tokens
**Server paths reviewed** (all HTML-accepting endpoints found by grep): Admin & Financial email center, bulk/test email, Marvflow messages/threads, staff messages, Financial messages — all pass through `RichTextSanitizer` (allow-list, fail-closed, size/node bounds, 2 profiles) on write, and `forDisplay`/`sanitizeEmail` on read. **Gap found & fixed:** `InvestorEmailController::show` returned stored `body_html` raw (a ` copy.php` file held the fix but declared a duplicate class and was never loaded) → now sanitised on output; stray file removed. `FinancialMailService::record` and `HandlesMarvflowThreads::saveThreadRow` store HTML supplied by their callers. **I did not trace every caller**; the Email Center controllers do sanitise before calling them, other callers are NOT VERIFIED — add a sanitise-on-write call inside these two methods as defence in depth.
**Client:** five `dangerouslySetInnerHTML` sinks (RichText, MarvflowThread, AdminEmailCenter ×2, MarvflowMessages) now go through `utils/safeHtml` — an independent DOMParser allow-list (no deps): drops script/style/iframe/svg/form…, strips every `on*`, allows `href` only http/https/mailto, `img src` only https or raster data URI, validated `style`, `ql-/rt-/mfm-` classes, forced `rel`. Fails closed.
**Tests:** server 22-payload battery × both profiles; client payload tests including "cannot read the auth token". *Not executed.*
**Token storage (not changed):** bearer token in `localStorage` (`auth_token`). Any XSS would expose it. Recommended compatible alternative: Sanctum **SPA cookie authentication** (HttpOnly + Secure + SameSite=Lax, CSRF cookie), same-site API/frontend domains, `supports_credentials`, remove token from JS; migrate behind a flag with a parallel period. Needs domain/CORS design and testing — decision D10. Interim: CSP header (`script-src 'self'`) on the SPA host, short token expiry/rotation.
